# base/head 与函数级上下文增强

## 目标

原始评审只向模型提供 unified diff 和少量 hunk 上下文。该阶段增加修改前与修改后完整文件的
安全获取，并在本地选择与变更相关的函数、类或行窗口，减少删除代码和跨局部语义导致的漏报。

## Provider 行为

### GitHub PR

1. 获取 PR 元数据并读取 base/head commit SHA。
2. 获取统一 diff。
3. 分页获取变更文件列表。
4. 按 base SHA 获取修改前文件。
5. 按 head SHA 获取修改后文件。

新增文件不读取 base 内容，删除文件不读取 head 内容。

### GitLab MR

1. 从 MR changes 响应读取 `diff_refs.base_sha` 与 `diff_refs.head_sha`。
2. 获取每个变更文件的修改前和修改后 raw 内容。
3. 新增和删除文件按对应侧跳过。

## 安全与预算限制

- 默认最多获取 30 个变更文件的上下文。
- 单个完整文件默认不能超过 200,000 字节。
- 单个分块发送给模型的上下文默认不能超过 16,000 字符。
- 包含空字节的二进制文件不会作为文本上下文。
- base/head 内容在写入恢复制品和 Prompt 前完成 Secret 脱敏。
- Trace 只记录完整文件内容哈希、选择策略、符号和行范围，不复制原始敏感上下文。

可配置变量：

```dotenv
REVIEW_AGENT_MAX_CONTEXT_FILES=30
REVIEW_AGENT_MAX_CONTEXT_FILE_BYTES=200000
REVIEW_AGENT_MAX_CONTEXT_CHARS=16000
```

## 函数级选择

Python 文件使用标准库 AST：

- 根据新增行定位修改后的函数或类。
- 根据删除行定位修改前的函数或类。
- 删除行没有对应新增行时，通过符号名称在 head 文件查找相同函数或类。
- 多个变更符号会合并为多个带行号的片段。

其他语言暂时使用通用策略：

- 以变更行为中心选择前后各 20 行。
- 重叠范围自动合并。
- 没有可靠行号时选择文件前 80 行作为降级上下文。

## Trace 与恢复

每个 Run 在本地制品目录保存脱敏后的 `contexts.json`。恢复任务时直接读取该文件，避免
重新请求 Provider，也确保恢复使用与初次执行相同的上下文。

Trace 的 `context_selector` 工具记录：

- `strategy`
- `symbols`
- `base_ranges`
- `head_ranges`
- `base_content_sha256`
- `head_content_sha256`

## 当前边界

- 函数级语义选择目前只对 Python 使用 AST。
- TypeScript、Java、Go 等语言尚未接入语法树解析器。
- LEFT/RIGHT 与删除行高置信度定位已经实现，详见[删除行定位](删除行定位.md)。
