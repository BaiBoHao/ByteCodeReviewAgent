# LEFT/RIGHT 删除行定位

## 问题

旧版本只允许 Finding 定位新增行。删除空值检查、权限校验或异常处理时，问题真正关联的是
旧文件中的删除行，因此即使模型发现问题，也只能被降级为“仅供参考”。

## 数据模型

Finding 现在包含：

```text
side: LEFT | RIGHT
line
old_line
new_line
```

- `RIGHT` 表示修改后文件的新增行，`new_line` 有值。
- `LEFT` 表示修改前文件的删除行，`old_line` 有值。
- `line` 保留为兼容字段，始终等于当前侧的有效行号。

## Prompt 约束

每个分块向模型同时提供：

- 允许使用的新增行号。
- 允许使用的删除行号。
- base/head 函数级上下文。
- unified diff。

模型必须在 JSON 中返回 `side`。新增代码问题使用 `RIGHT`，删除代码导致的问题使用
`LEFT`。

## 置信度校验

高置信度要求：

1. 模型声明高置信度。
2. 文件路径与当前分块一致。
3. `RIGHT` 行号存在于新增行集合，或 `LEFT` 行号存在于删除行集合。
4. Finding 包含具体证据。

侧别错误、行号不存在或缺少证据时，Finding 会降级为中低置信度并进入“仅供参考”。

## SQLite 迁移

`findings` 表新增：

```text
side TEXT NOT NULL DEFAULT 'RIGHT'
old_line INTEGER
new_line INTEGER
```

启动存储时会检查旧表结构并执行增量 `ALTER TABLE`。历史 Finding 默认视为 `RIGHT`，
原始 `line` 会作为兼容的新文件行号返回。

## 输出展示

- Markdown 报告标注 `LEFT/删除侧` 或 `RIGHT/新增侧`。
- 本地 Web Finding 卡片显示“删除侧”或“新增侧”标签。
- API 同时返回 `side`、`old_line` 和 `new_line`。
- Fingerprint 包含侧别，避免左右侧同一行号发生误去重。

## 验证样例

`ReviewProjectTest` 删除了空订单保护逻辑。演示模型返回旧文件第 20 行、`side=LEFT`，
系统确认该行属于删除行集合，因此将除零问题保留为高置信度 Finding。
