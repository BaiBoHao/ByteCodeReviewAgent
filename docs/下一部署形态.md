# 下一部署形态：VS Code 插件与本地 Runner

## 决策

本地 Web 节点完成后，下一部署形态优先选择：

> VS Code 插件 + 本地 Review Agent Runner sidecar

不优先选择 Edge 扩展、JetBrains 插件或云端 Web 服务。

## 选择理由

### 复用率最高

- Python Runner 已提供本地 FastAPI。
- React 与 Ant Design 页面已经完成。
- VS Code Webview 可以复用现有 React 组件和 API 客户端。
- SQLite、Trace、预算、checkpoint 和 resume 无需重写。

### 最接近日常开发流程

- 可评审当前文件、未提交修改、暂存区和当前分支。
- Finding 可以直接跳转到编辑器行号。
- LEFT/RIGHT 可以映射到 VS Code Diff Editor 两侧。
- 用户不需要在 IDE 和浏览器之间切换。

### 安全边界清晰

- Runner 继续只监听 `127.0.0.1`。
- 模型 Key 使用 VS Code SecretStorage 或操作系统凭证库。
- 插件不直接持有 Python 评审逻辑。
- 云端模型仍只接收本地脱敏后的必要上下文。

## 产品结构

```text
VS Code Extension
  ├─ Activity Bar / Tree View
  ├─ Review Commands
  ├─ Findings / Trace Webview
  ├─ SecretStorage
  └─ Editor / Diff Navigation
             │
             │ localhost HTTP
             ▼
Review Agent Runner
  ├─ FastAPI
  ├─ ReviewService
  ├─ base/head Context
  ├─ LEFT/RIGHT Findings
  ├─ SQLite / Trace
  └─ Model Gateway
```

## 插件 MVP

### 命令

```text
Review Agent: 评审当前文件
Review Agent: 评审未提交修改
Review Agent: 评审已暂存修改
Review Agent: 评审当前分支
Review Agent: 评审 PR/MR
Review Agent: 查看历史运行
Review Agent: 恢复失败任务
```

### 页面

- 左侧 Activity Bar 入口。
- 最近运行 Tree View。
- 复用当前 React 评审页面作为 Webview。
- Finding 点击后打开对应文件和行号。
- LEFT Finding 打开旧文件侧，RIGHT Finding 打开新文件侧。
- Trace 面板显示工具、上下文、费用和模型响应。

### Runner 生命周期

1. 插件启动时检查本地 Runner 健康状态。
2. 未运行时启动 sidecar，并使用随机可用端口。
3. 插件保存当前 Runner 端口和会话令牌。
4. IDE 关闭时正常停止由插件启动的 Runner。
5. Runner 异常退出时显示可恢复提示，而不是静默重启任务。

## 插件前需要补充的安全能力

- API 增加随机会话令牌。
- 每个修改请求必须携带会话令牌。
- Webview 通过 URL Fragment 接收令牌，React 读入内存后立即清除 Fragment。
- Runner 校验 Origin 与 Host。
- 禁止任意远程地址监听。
- 模型 Key 从 SecretStorage 注入 Runner 环境，不写入插件配置 JSON。
- 明确限制本地文件读取范围为当前工作区或用户显式选择的 diff。

## 分发形式

第一版建议提供两个制品：

```text
review-agent-runner.exe
bytecode-review-agent.vsix
```

开发阶段可以继续使用：

```text
python -m bytecode_review_agent serve
```

插件优先连接开发 Runner；正式打包后再自动启动 EXE sidecar。

## 后续顺序

### 第二：Edge/Chrome 扩展

适合 GitHub/GitLab PR 页面。复用 React 组件，但只负责 URL、侧边栏和行号跳转，
评审仍由本地 Runner 执行。

### 第三：JetBrains 插件

使用 Kotlin 外壳和 JCEF 复用页面，增加 Tool Window、Gutter 和 Diff Viewer 集成。
Java 企业团队明确需要时可以提前。

### 最后：云端团队版

需要额外建设 OAuth、Webhook、PostgreSQL、任务队列、多租户、审计、权限和数据删除策略，
不应直接把当前 SQLite 本地服务暴露到公网。
