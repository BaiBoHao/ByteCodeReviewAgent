# Edge 侧边栏扩展与安全配对

## 背景

用户决定跳过 VS Code 后续开发，把 Edge 扩展作为下一部署形态。扩展应直接复用现有本地
Runner，不保存模型密钥，也不向 GitHub 或 GitLab 页面注入脚本。

## 本次完成

- 新增 Manifest V3 浏览器扩展，使用 Chromium Side Panel 展示 React 与 Ant Design 界面。
- 自动读取活动标签页中的 GitHub PR 或 GitLab MR 地址。
- 支持提交评审、轮询任务、展示 Findings、LEFT/RIGHT 侧别与 Trace。
- 新增 8 位一次性进程配对码，换取 Runner 会话令牌。
- 会话令牌只保存在 `chrome.storage.session`，浏览器重启后需要重新配对。
- Runner CORS 仅允许回环页面、合法 Chromium 扩展 ID 和 VS Code Webview。
- 配对连续失败 5 次后锁定到 Runner 重启，比较过程使用恒定时间函数。
- 本地 Web 配置卡片增加扩展配对码展示。
- 重新构建 Windows Runner，确保 EXE 包含配对接口和最新 Web 页面。

## 当前边界与下一步

- 尚未在用户的日常 Edge 配置中执行“加载解压缩的扩展”，该操作会改变浏览器状态，需要
  用户确认后再进行。
- 扩展当前支持 GitHub.com 与 GitLab.com；自建 GitLab 域名后续应改为用户可配置白名单。
- 生产构建的单个前端脚本约 871 KB，功能不受影响，后续可按页面或 Trace 弹窗拆包。
- 正式发布到 Edge Add-ons 之前还需要补图标、隐私说明、签名和商店资料。
- 全量 Ruff 仍有 55 条历史风格告警，主要来自 Typer 参数默认值、旧类型注解与既有导入；
  本节点未做无关的全库格式化或重构。
